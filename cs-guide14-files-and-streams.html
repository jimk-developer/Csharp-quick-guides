Making Data Last Beyond the Program

Every variable a program creates disappears the moment that program ends, unless the data is saved somewhere more permanent. This guide covers the difference between temporary and permanent storage, how files and directories are organized, the data hierarchy from characters up to files, sequential and random access files, the stream objects C# uses to move data in and out of a program, reading and writing text files, searching through file data, and converting whole objects into a form that can be saved and restored.

💾 Storage Fundamentals

Volatile (Temporary) Storage

Random access memory (RAM) holds data only while a program runs. A value stored in a variable is lost the moment the program ends or the computer loses power.

Nonvolatile (Permanent) Storage

Hard disks, solid state drives, USB drives, magnetic tape, and optical discs retain data even after the program that created it ends or the computer is powered off.

Writing a C# program's source code and saving it to disk uses permanent, nonvolatile storage, not temporary storage. It is the values held in a running program's variables, kept in RAM while that program executes, that count as temporary, volatile storage.

Because data stored on a disk can still be deliberately erased or overwritten, some programmers prefer the term persistent storage over "permanent" storage; the data survives a loss of power, but it isn't necessarily permanent in every sense.

Storing data on a persistent storage device is described as writing to a file. Copying data from a file on a storage device back into RAM, so a running program can work with it, is described as reading from that file.

File Sizes

File and storage sizes are measured using a family of related units, each one roughly a thousand times larger than the one before it.

Unit Approximate Size
Bit A single binary digit, 0 or 1
Byte 8 bits
Kilobyte (KB) About 1,000 bytes
Megabyte (MB) About 1 million bytes
Gigabyte (GB) About 1 billion bytes
Terabyte (TB) About 1 trillion bytes

📁 Files and Paths

A computer file is a collection of information stored together on a nonvolatile device. Most users organize their files into directories, also known as folders; the two terms are used synonymously.

A file's path is the combination of the disk drive plus the complete hierarchy of directories in which that file resides, describing exactly where to find it. The root directory is the top-level directory of a drive, the starting point every other directory on that drive branches out from.

Text Files vs. Binary Files

Text File

Stores data encoded as readable text, using a character set such as Unicode, so the raw contents can be opened and read directly.

Binary File

Stores unencoded data items in a format meant for a specific program to interpret, such as the formats used for music or image files, rather than for direct human reading.

Despite their differences, text and binary files share an important characteristic: both ultimately store their data as a sequence of bytes on a nonvolatile device, and both must be opened before a program can use them and closed again afterward.

🗂️ File and Directory Classes

The File and Directory classes, both part of the System.IO namespace, provide methods for accessing information about files and folders. The File class contains methods that let you access information about individual files, while the Directory class provides similar information about directories, or folders.

The File class lives in the System.IO namespace, not a namespace named System.IOFile; there is no such namespace in C#. Most of the File class's methods are static, so you call them directly through the class name itself, such as File.Exists("data.txt"), without needing to instantiate a File object first.

🧱 The Data Hierarchy

Data used by business applications is commonly organized into a data hierarchy, where each level combines to build the next.

Level Description
Character Any single letter, number, or special symbol, such as punctuation, that makes up data
Field A meaningful group of characters, such as a name or a price
Record A collection of fields containing data about one entity, such as all the fields describing a single customer
File A collection of records
Characters combine to form fields, fields combine to form records, and records combine to form files, each level building directly on the one below it. A single value like a customer's phone number is only a field on its own; it becomes part of a record only once it is grouped together with the other fields describing that same customer.

🔀 Sequential vs. Random Access Files

Sequential Access File

Records are read in the order of their position in the file, often ordered by a key field, the field that uniquely identifies each record.

Random Access File

Records do not need to be read in sequence; any record can be accessed directly, in any order, regardless of its position in the file.

Opening and Closing Files

A C# application opens a file by creating an instance of an appropriate file-processing class, such as FileStream, StreamReader, or StreamWriter, associated with that file's path. Once an application is finished using a file, it should close the file, releasing the system resources tied up in keeping it open, either by explicitly calling Close() or by using a using block that closes the file automatically.

🌊 Streams

A stream is a pipeline, or channel, for input and output. When you perform an input operation, you can picture bytes flowing into your program from an input device through a stream object; the reverse happens during output, with bytes flowing out of the program through a stream toward an output device.

Standard Console Streams

Stream Purpose
Console.In The standard input stream, typically the keyboard
Console.Out The standard output stream, typically the console window
Console.Error The standard error stream, used for error messages

File-Processing Classes

Class Purpose
FileStream Processes files as raw bytes
StreamReader Processes text input from a file
StreamWriter Processes text output to a file

FileMode and FileStream Properties

When constructing a FileStream, a FileMode value specifies how the file should be opened.

FileMode Behavior
FileMode.Create Opens an existing file and empties it, resulting in a file that is zero bytes in size; creates a new file if one does not already exist
FileMode.Open Opens an existing file; if the file does not exist, this throws an exception rather than creating one

A FileStream's CanRead property indicates whether that FileStream supports reading, letting code check a stream's capabilities before attempting an operation on it.

✍️ Reading and Writing Text Files

Example: Writing Text to a File

FileStream journalFile = new FileStream("journal.txt", FileMode.Create, FileAccess.Write);
StreamWriter logWriter = new StreamWriter(journalFile);

logWriter.WriteLine("Finished the C# guide series today.");
logWriter.Close();

Wrapping the FileStream in a StreamWriter, as logWriter does here, is exactly what makes methods like WriteLine() available for sending text to the underlying file.

Example: Reading Text from a File

StreamReader logReader = new StreamReader("journal.txt");
string textLineIn = logReader.ReadLine();

while (textLineIn != null)
{
    Console.WriteLine(textLineIn);
    textLineIn = logReader.ReadLine();
}
logReader.Close();
The first call to ReadLine(), made before the while loop even begins, is known as a priming read: a read performed ahead of time so the loop's condition has a real value to test the very first time it is checked. ReadLine() returns null once it reaches the end of the file, which is exactly the condition while (textLineIn != null) relies on to stop the loop after every line has been processed, but not before.

Tokens and Delimiters

A delimiter is a character used to mark the boundary between data items in a text file. A token is a character or group of characters that has some meaning, such as one complete field extracted from a line of text; more broadly, a token can refer to any meaningful block of text within a string. A field delimiter separates individual fields within a record, while a record delimiter (often just a new line) separates one full record from the next.

A CSV file ("comma-separated values") is a common example, using a comma as its field delimiter.

Example: Splitting a Delimited Line into Tokens

string recordLine = "E204,Priya Shah,Warehouse,22.50";
string[] fields = recordLine.Split(',');

// fields[0] is "E204", fields[1] is "Priya Shah", and so on

The Split() method, a member of the string class, takes a character delimiter parameter and separates a string into an array of substrings, breaking the original string apart at every occurrence of that delimiter.

A CSV file uses a comma as its field delimiter, not a semicolon. While some regional spreadsheet formats do use a semicolon-delimited variant, the standard, defining characteristic of a CSV file is the comma.

Storing Object Data in a Sequential File

To store data from an object in a sequential file, you must convert that object's field values into delimited text, such as a comma-separated line, and write that resulting string out to the file; a sequential text file has no way to store an object directly as an object, only as the text representing its data.

🔎 Searching Files

While a file is open, C# tracks the byte number of the next byte to be read using a file position pointer. As a program reads through a file, this pointer automatically advances.

The Seek() method can be used to reposition the file position pointer while reading a file, in combination with the SeekOrigin enumeration, which specifies whether the new position is measured from the beginning of the file, the current position, or the end of the file. Repositioning the pointer this way lets a program process the same file's data more than once without closing and reopening it.

Example: Searching a Sequential File

StreamReader payrollReader = new StreamReader("payroll.txt");
double salaryThreshold = 20.00;
string recordLine = payrollReader.ReadLine();

while (recordLine != null)
{
    string[] fields = recordLine.Split(',');
    double hourlyRate = double.Parse(fields[3]);

    if (hourlyRate > salaryThreshold)
    {
        Console.WriteLine(recordLine);
    }

    recordLine = payrollReader.ReadLine();
}
payrollReader.Close();

To search a sequential file for records where a numeric field is greater than a user-supplied value, this same pattern applies generally: a loop reads each record in turn, splits it into its individual fields, and tests the field of interest with an if statement, continuing until the entire file has been read.

📦 Serialization and Deserialization

Serialization is the process of converting an object into a stream of bytes, most often so it can be written to a file securely and efficiently as a single unit, rather than manually breaking it apart into individual delimited fields. Deserialization is the reverse process: converting a stream of bytes read back from a file into a fully reconstructed object.

Example: A Serializable Class

[Serializable]
class Contact
{
    public string Name;
    public string Email;
}

The [Serializable] attribute marks a class, and by extension its instance variables, as eligible to be converted into a stream of bytes. Performing the actual conversion typically relies on a formatter class from a namespace such as System.Runtime.Serialization.Formatters.Binary, which handles translating a marked object's data into bytes and back again.

To convert a C# object into a stream of bytes, you serialize it: mark its class with the [Serializable] attribute, then use a serialization formatter to write that object out to a stream, rather than manually converting each field into delimited text yourself.
