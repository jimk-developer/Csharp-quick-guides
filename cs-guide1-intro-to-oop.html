What Is Object-Oriented Programming?

Every piece of software starts with a programming language: a system of special words and grammar used to write instructions that direct a computer. C# is an object-oriented and component-oriented language built for creating modern applications. This guide covers the programming process, the vocabulary of object-oriented programming, and the steps needed to write, compile, and run your very first C# program.

💻 The Programming Process

Programs, Software, and Hardware

A computer program is a set of written instructions that tells a computer what to do. The set of special words and grammar you use to write those instructions is called a programming language. Programs fall into the broader category of software, while the physical devices that make up a computer system (the screen, keyboard, processor, and storage) are called hardware.

⚙️

System Software

Programs that operate the computer itself, such as an operating system. Works in the background so other programs can run.

🧮

Application Software

Programs that allow users to complete tasks, such as a word processor, a game, or a custom business application you write yourself.

🖥️

Hardware

The physical devices that make up a computer system. Hardware runs the software, but it cannot do anything on its own.

Machine Language and High-Level Languages

Internally, a computer is built from circuitry that consists of tiny on/off switches. Machine language is software expressed directly as a series of 1s and 0s, where 1 represents a switch that is on and 0 represents a switch that is off. Writing programs this way is technically possible but extremely impractical for humans.

A high-level programming language solves this problem by using a limited vocabulary of reasonable keywords, such as read, write, or add, instead of requiring you to reference raw sequences of switches. High-level languages also let you assign reasonable names to areas of computer memory, and each one has its own syntax, the set of grammar rules that govern how the language can be used correctly.

Concept Description
Machine language The most basic circuitry-level language; expressed as 1s and 0s representing on/off switches
High-level language Uses reasonable keywords and named memory locations instead of raw switch sequences
Source code The program statements you write in a high-level language
Compiler Software that translates source code statements into machine code

A compiler translates your high-level source code into machine code the processor can execute. If you use the language incorrectly, the compiler issues an error message describing the syntax error. Getting a program to compile, however, does not guarantee it produces the right results. The logic of a program is the sequence of statements and methods executed in the correct order to produce the desired outcome.

Debugging

Debugging is the process of removing all syntax errors and logical errors (sometimes simply called bugs) from a program so it compiles cleanly and produces correct results. Every programmer debugs constantly; it is a normal and expected part of writing software, not a sign that something has gone wrong with the process.

🧩 Procedural and Object-Oriented Programming

Procedural Programming

A procedural program is built by creating and naming computer memory locations that can hold values. These named locations are called variables, and each one is referenced using a one-word name called an identifier. Procedural programs group related operations into logical units called procedures or methods. A program calls (or invokes) a method to input, manipulate, or output one or more values, and a single procedural program can easily contain hundreds of variables and thousands of method calls.

Object-Oriented Programming

Object-oriented programming (OOP) is an extension of procedural programming. Rather than focusing only on variables and method calls, OOP organizes a program around objects, concrete entities that have attributes (characteristics) and behaviors (the things they do). The collective value of all of an object's attributes at a given moment is called its state.

An object-oriented approach to a problem means identifying the objects needed to accomplish a task and writing classes that describe those objects, so each object can maintain its own data and carry out tasks when other objects request them. OOP was originally developed for two kinds of applications:

🧪 Computer Simulations

Programs that attempt to mimic real-world activities so the underlying processes can be studied or improved.

🖱️ Graphical User Interfaces

Programs that let users interact with software through graphical controls, such as windows, buttons, and menus, instead of typed commands.

Procedural programming asks "what steps need to happen?" OOP asks "what objects exist, and what can each one do for itself?" Modern languages like C# blend both ideas: methods still carry out steps, but those methods belong to objects.

🧬 Features of Object-Oriented Programming Languages

For a language to be considered truly object-oriented, it must support five features: classes, objects, encapsulation and interfaces, inheritance, and polymorphism.

📐

Class

Describes a category of potential objects, including the attributes and behaviors those objects will have. A class is the blueprint; it does not do anything by itself.

📦

Object

An instance of a class: a concrete entity created from the blueprint. The values held by an object's attributes are called its properties.

🔒

Encapsulation

Packaging an object's attributes and methods into a single, cohesive, undivided unit, often compared to a black box you use without needing to know how it works internally.

🧬

Inheritance

The ability to extend an existing class to create a more specific class. The new class keeps every attribute and method of the general class and typically adds more of its own.

🎭

Polymorphism

The ability to create methods that act appropriately depending on context, so a program can tell several same-named methods apart based on the object using them.

The interface of a method is the format of the interaction between that method and an object: what information the method needs and what it hands back. Many programmers describe well-encapsulated objects the same way they describe everyday devices: you do not need to understand a device's internal mechanisms to use it correctly, you only need to know its interface.

Example: A Simple Class Definition

class Robot
{
    // Attributes (the data this object holds)
    public string Name;
    public int BatteryLevel;

    // A behavior (method) the object can perform
    public void Greet()
    {
        Console.WriteLine("Beep boop, ready to assist.");
    }
}

This original example defines a Robot class with two attributes (Name and BatteryLevel) and one behavior (Greet). Creating a Robot object from this class produces a single instance whose properties can hold its own values; encapsulating that data and behavior together means anything that uses a Robot only needs to know it can call Greet(), not how the method is implemented internally.

Term Meaning
Attribute A characteristic of an object
Property The value held by an object's attribute
State The collective value of all of an object's attributes at a point in time
Behavior What an object does; implemented as a method
Instance An object; a tangible example of a class

🟣 The C# Programming Language

C# was developed as an object-oriented and component-oriented language and is part of Microsoft Visual Studio. It is designed for building applications that run on Windows computers, and it lets you treat every piece of data as an object so you can consistently apply object-oriented principles throughout a program.

🪟 Compared to Visual Basic

C# offers a similar graphical interface experience but is generally considered more concise.

⚙️ Compared to C++

C# was modeled after C++, but it is designed to be easier to learn and work with.

☕ Compared to Java

C# is similar to Java in many ways, but is considered more thoroughly and consistently object-oriented.

C# is not just "a language for Windows forms." Because it treats every value as an object and enforces object-oriented principles throughout, the concepts you learn in this guide (classes, objects, encapsulation, inheritance, and polymorphism) apply to nearly everything you will build with it.

✏️ Writing a C# Program That Produces Output

Literal Strings and Arguments

A literal string is a series of characters that will be used exactly as entered. In C#, a literal string appears between double quotation marks. An argument is a piece of information a method needs to perform its task, and arguments to a method always appear inside parentheses.

The WriteLine() Method

The WriteLine() method is a built-in C# method that displays output on the screen and then positions the cursor on the next line, ready for the next output statement. It belongs to the Console class and is typically called as Console.WriteLine().

Method Headers and Method Bodies

A method header is the first line of a method. It includes the method's name and information about what will pass into and be returned from the method. A method body is everything between the method's curly braces; it holds every instruction the method carries out. Whitespace, any combination of spaces, tabs, and blank lines, can be added freely to make code easier to read without changing how it runs.

Every runnable C# program needs a method named Main(). The word void in a method header indicates that the method does not return a value when called, and static indicates that the method runs through the class itself rather than through an object created from that class. A class that contains a Main() method is called an application class; a class without one is a non-application class and cannot be run on its own.

Example: A Minimal C# Program

using System;

namespace Guide1Examples
{
    class Program
    {
        static void Main()
        {
            // Display a greeting and move to the next line
            Console.WriteLine("Hello, future developer!");
        }
    }
}

Reading this from the outside in: Guide1Examples is a namespace, Program is an application class because it contains Main(), and "Hello, future developer!" is the literal string argument passed to WriteLine().

🔤 Selecting Identifiers

An identifier is the name of a program component, such as a variable, class, or method. C# identifiers must follow these rules:

  • May contain up to 511 characters
  • Must begin with an underscore, the at sign (@), or a letter
  • May contain only letters, digits, underscores, and the at (@) sign
  • Cannot be a C# reserved keyword, such as class or void
An identifier like 1stPlace is illegal because it begins with a digit. Renaming it firstPlace or place1 fixes the problem while keeping the intent clear.

An identifier prefixed with @ is called a verbatim identifier. This feature lets you use names that would otherwise collide with a C# reserved keyword, which is especially useful when incorporating code originally written in a language that does not share C#'s keyword list.

Casing Conventions

Style Rule Example
Camel casing
(lower camel casing)		 First letter lowercase; each new word capitalized batteryLevel
Pascal casing
(upper camel casing)		 Every new word capitalized, including the first BatteryLevel
A common convention is to use Pascal casing for class names and method names, and camel casing for local variables. This guide's Robot class and Greet() method follow Pascal casing; a local variable inside a method would typically follow camel casing instead.

💬 Adding Comments to a Program

Even a simple C# program takes several lines of code, and large programs take many more. Program comments are nonexecuting statements you add to document a program for yourself and other programmers. When you comment out a statement, you turn executable code into a comment so the compiler ignores it, which is a handy way to test a program without a particular line.

Comment Type Syntax Use
Line comment // Starts a comment that runs to the end of the current line; can stand alone or follow code
Block comment /* ... */ Starts with /* and ends with */; can span as many lines as needed
XML-documentation comment <tag> Uses special tags within angle brackets to create generated documentation for a program

Example: Comment Styles

// A line comment describing the next statement
Console.WriteLine("Hello, future developer!");

/* A block comment that can
   stretch across multiple lines
   to explain something in more detail */

// Console.WriteLine("This line is commented out.");
Write comments that explain why code does something, not just what it does. The code itself already shows what is happening; a good comment adds the context a reader cannot get from the statement alone.

📦 Using the System Namespace

A namespace is a construct that acts like a container, providing a way to group similar classes together. When you need to repeatedly use a class from the same namespace, you can shorten your statements by adding a clause that tells the compiler which namespace to use. This is done with a using clause, also called a using directive.

Syntax: With and Without a Using Directive

// Without a using directive: fully qualify the class
System.Console.WriteLine("Hello, future developer!");

// With a using directive at the top of the file:
using System;
// ...now you can shorten every later call:
Console.WriteLine("Hello, future developer!");

Console belongs to the System namespace, which is why a using System; directive appears near the top of nearly every C# console program you will write.

⌨️ Compiling and Executing from the Command Line

Viewing a C# program's output takes two steps: first the source code is compiled into intermediate language (IL), and then the just in time (JIT) compiler translates that intermediate code into executable machine code. You can trigger this process from either the command line or an IDE.

📄
Source Code (.cs)
The C# statements you write in a text file
→
⚙️
Intermediate Language
Produced by the C# compiler (csc)
→
🖥️
Machine Code
Produced by the JIT compiler at run time

The command line is the operating system's text interface, and the command prompt is the request for input that appears at the beginning of it. A Developer Command Prompt is a special version of the command prompt with settings already configured for compiling and running C# programs.

Step Command Purpose
1 cd C#\Guide01 Changes the current directory to the folder that holds your program
2 csc Greeting.cs Compiles the source file into an executable program
3 Greeting Runs the compiled program (the .exe extension is optional)

Example: Compiling from the Developer Command Prompt

C:\> cd C#\Guide01
C:\C#\Guide01> csc Greeting.cs
C:\C#\Guide01> Greeting
Hello, future developer!

🛠️ Compiling and Executing Using Visual Studio

The Integrated Development Environment (IDE) is a program development environment where you issue commands using menus and buttons instead of typed commands. Visual Studio is Microsoft's IDE for C#, and it offers several advantages over compiling from the command line.

🖌️

Syntax Coloring

Code is displayed in color, making keywords, strings, and identifiers easy to tell apart at a glance.

⌨️

Statement Completion

The IDE suggests and automatically completes statements as you type, reducing typing errors.

🐞

Error Navigation

Double-clicking an error message moves the cursor directly to the line of code containing the problem.

🧰

Debugging Tools

Built-in tools beyond simple error messages help you trace and resolve logic errors during execution.

When you start a new console application in Visual Studio, the IDE generates a console template: a starting set of statements, including the using directive, namespace, class, and Main() method, that you can build on right away instead of typing every line from scratch.

Whether you compile from the Developer Command Prompt or from Visual Studio, the underlying process is the same: source code becomes intermediate language, and intermediate language becomes machine code at run time. The IDE simply wraps that process in a more convenient, visual environment.
