Building Your Own Types

Everything built so far in this series has relied on data types C# already provides. Writing your own classes lets you design custom types that model exactly the kind of data and behavior your program needs. This guide covers how classes are structured and instantiated, how properties control access to an object's data, how constructors initialize new objects, how operators can be taught to work with custom types, how arrays of objects are sorted and searched, and how classes are cleaned up when they are no longer needed.

🧱 Class Fundamentals

A class is a blueprint or template that describes what objects created from it will look like and how they will behave. An application class, the kind that contains Main(), differs from every other class in a program specifically because it holds that entry point method; any other class exists purely to describe objects that the application creates and uses.

Instance Variables and Instance Methods

The data components of a class that can differ from one object to the next are called instance variables, more commonly referred to as fields, a term used specifically to distinguish them from local variables and other kinds of variables in a program. Each object stores its own separate copy of every instance variable, so changing one object's field has no effect on any other object created from the same class.

Every object of a particular class shares the exact same blocks of statements, which can be executed by calling the object's instance methods. The values held by an object's fields at any given moment make up that object's state.

Example: A Simple Class

class Vehicle
{
    // Instance variables (fields)
    private string make;
    private int topSpeed;

    // An instance method
    public void Describe()
    {
        Console.WriteLine("{0} has a top speed of {1} mph.", make, topSpeed);
    }
}

Class Clients

A class client, also called a class user, is any program that instantiates objects of another, prewritten class rather than defining that class itself. A single well-written class can serve as many different class clients across many different programs, each one creating and using its own objects from that same class definition.

🔐 Class Creation and Access Modifiers

The Class Header

A class header is the part of a class definition that contains an optional access modifier, the keyword class, and an identifier naming the class. Everything that follows the header, enclosed in curly braces, forms the body of the class: its fields, properties, constructors, and methods.

Class Access Modifier Meaning
public Access to the class is not limited at all
protected Access is limited to the class itself and to any classes derived from it
internal Access is limited to the assembly, a group of code modules compiled together, that the class belongs to
private Access is limited to another class the class belongs to, most often used for classes nested inside another class

Default Field Access and Information Hiding

If you do not explicitly include an access specifier for a field in a C# class, that field defaults to private access, exactly as with a method. Deliberately declaring fields as private and exposing controlled access to them through public methods, or more commonly through public properties, is a hallmark of information hiding: a feature found in all object-oriented languages that combines private data with public accessors to protect an object's internal state from being changed in unexpected ways.

Combining private fields with public accessor methods or properties achieves information hiding by giving outside code a controlled, well-defined way to interact with an object's data, without allowing that outside code to reach in and modify the raw fields directly.

C#'s predefined types, such as int, double, and char, are examples of the language's built-in intrinsic types; classes you write yourself become new types you can use right alongside those built-in ones.

🧩 Composition

Composition describes a has-a relationship, where an object of one class is used as a field within an object of another class. Rather than inheriting behavior, a composed object simply becomes part of the containing object's data.

Example: Composition (a Has-a Relationship)

class Engine
{
    public int Horsepower { get; set; }
}

class Car
{
    // A Car has-a Engine: composition
    private Engine engine;

    public Car(int horsepower)
    {
        engine = new Engine();
        engine.Horsepower = horsepower;
    }
}

Here, a Car object contains an Engine object as one of its fields; a car "has an" engine, which is exactly the relationship composition is used to model.

✨ Instantiation and Objects

To instantiate means to create an object: a concrete instance of a class, brought into existence by calling one of that class's constructors with the new operator.

Syntax: Instantiating an Object

Vehicle sedan = new Vehicle();
The new keyword is required to instantiate an object. Writing Vehicle sedan = Vehicle();, without new, is a compiler error; a constructor is the method that creates the instance, and it must be explicitly invoked with new.

Reference Types vs. Value Types

C#'s data types fall into two broad categories.

Value Type

Holds an actual data value directly, such as an int or a bool. Copying a value type variable copies the value itself.

Reference Type

Holds the memory address, or reference, of where the actual object data is stored, rather than the data itself. Every class you write creates a reference type.

Because an object's identifier references a specific memory location rather than holding the object's data directly, you can call any class variable a reference type. This is also why passing an object to a method gives that method access to the actual object, not an independent copy of it, the same behavior seen when passing an entire array to a method.

🏷️ Properties

A property is the class member that provides controlled access to a field. A property is written with a get accessor (or getter), used to retrieve a field's value, and a set accessor (or setter), used to assign a new value to that field using the property's name.

Example: A Property with Get and Set Accessors

class Product
{
    private decimal price;

    public decimal Price
    {
        get { return price; }
        set { price = value; }
    }
}

Inside a set accessor, the identifier value automatically holds whatever data was assigned to the property. value acts like a keyword in this one specific circumstance, which makes it a contextual keyword rather than a full reserved keyword.

Example: Using a Property

Product widget = new Product();
widget.Price = 19.99m;
// Executes the set accessor, assigning 19.99 to the price field

Console.WriteLine(widget.Price);
// Executes the get accessor, retrieving the price field's value

Read-Only Properties

A property written with only a get accessor, and no set accessor at all, is a read-only property. Its value can be retrieved from outside the class, but it cannot be assigned a new value from outside the class; a read-only property's value can typically only be set inside the class itself, such as within a constructor.

Auto-Implemented Properties

An auto-implemented property, also called an automatic property, is a concise way to write a property when its get and set accessors need no logic beyond simply storing and retrieving a value. The compiler automatically generates a hidden backing field to store the data, so you never declare that field yourself.

Example: An Auto-Implemented Property

class Product
{
    public string Sku { get; set; }
}

Auto-implemented properties are most appropriate when a property does not need any validation or additional logic in either accessor; as soon as a property needs to check or transform a value before storing it, a fully written property with an explicit backing field becomes necessary instead.

A property, whether fully written or auto-implemented, always provides access to a field: either a field you declared yourself, or the compiler-generated backing field behind an auto-implemented property.

👉 The this Reference

The this reference is implicitly and invisibly passed to every instance method and every property accessor. It refers to the invoking object: whichever specific object the method or accessor was called on. Because it is passed automatically rather than appearing in the parameter list, this is described as an implicit parameter.

Only nonstatic methods receive a this reference. A static method is not tied to any particular object, so there is no invoking object for this to refer to inside it.

Most of the time, code inside a class can refer to its own fields without writing this explicitly, since C# already knows which object's fields are meant. An explicit this becomes necessary specifically when a method's parameter name is identical to one of the class's field names, which would otherwise make the field inaccessible inside that method.

Example: When an Explicit this Is Required

class Ticket
{
    private int seatNumber;

    public void SetSeatNumber(int seatNumber)
    {
        // Without "this.", seatNumber = seatNumber; would
        // just assign the parameter to itself and do nothing useful
        this.seatNumber = seatNumber;
    }
}

Here, the parameter seatNumber has the same name as the field seatNumber. Writing this.seatNumber explicitly tells the compiler you mean the field that belongs to the invoking object, distinguishing it from the parameter of the same name.

🏗️ Constructors

A constructor is a special method that creates, or instantiates, an object of a class and typically initializes its fields. A constructor always shares its class's name and never declares a return type, not even void.

Default Constructors

If you do not write any constructor for a class at all, C# automatically writes a default constructor for you: a parameterless constructor that takes no arguments and sets every field to its default value, such as 0 for numeric fields, false for bool fields, and null for reference-type fields.

As soon as you write even one constructor of your own, C# stops automatically supplying that default constructor. If you write a constructor that requires an argument and you also want the class to support being created with no arguments, you must explicitly write your own parameterless constructor as well; it will no longer be generated for you automatically.

Writing an explicit default constructor yourself is most useful when you want newly created objects to start out with specific, meaningful values rather than the generic system defaults of 0, false, or null.

Overloading Constructors

Just like ordinary methods, constructors can be overloaded: a class can define multiple constructors as long as each one has a different parameter list, so the compiler can always tell them apart without ambiguity.

Example: Overloaded Constructors

class Employee
{
    public string Name { get; set; }
    public decimal HourlyRate { get; set; }

    public Employee()
    {
        Name = "Unassigned";
        HourlyRate = 15.00m;
    }

    public Employee(string name, decimal hourlyRate)
    {
        Name = name;
        HourlyRate = hourlyRate;
    }
}

Constructor Initializers

Rather than repeating the same initialization code across several overloaded constructors, a constructor initializer can be used to indicate that another instance of the class's constructor should execute first, before any statements in the current constructor's own body.

Example: A Constructor Initializer

class Employee
{
    public string Name { get; set; }
    public decimal HourlyRate { get; set; }

    public Employee(string name, decimal hourlyRate)
    {
        Name = name;
        HourlyRate = hourlyRate;
    }

    // This parameterless constructor calls the constructor above first
    public Employee() : this("Unassigned", 15.00m)
    {
    }
}

The : this(...) syntax after the parameterless constructor's parameter list is the constructor initializer; it runs the two-parameter constructor first, using the supplied default values, before the parameterless constructor's own (empty) body executes.

The readonly Modifier

The readonly modifier marks a field that can be assigned a value either when it is declared or inside a constructor, but never changed after that. Unlike const, whose value must be known and fixed at compile time, readonly allows a value to be determined at runtime, such as when an object is actually created, while still guaranteeing it cannot be modified afterward.

Example: A readonly Field Assigned in a Constructor

class Order
{
    public readonly DateTime PlacedOn;

    public Order()
    {
        PlacedOn = DateTime.Now;
        // PlacedOn is fixed the moment this object is created,
        // and cannot be reassigned by any code afterward
    }
}
Use readonly in a situation like this, where the correct value is not known until an object is actually created at runtime, such as an order's placement timestamp or a uniquely generated identifier. Use const instead whenever the value is already known and fixed before the program even runs.

Also worth noting: a named constant declared within a class is always implicitly static, even though no explicit static keyword can be written on it; it belongs to the class itself rather than to any individual object.

🎁 Object Initializers

An object initializer assigns starting values to an object's accessible properties or fields at the moment it is instantiated, without needing a specifically parameterized constructor written for that purpose.

Example: An Object Initializer

Product giftBasket = new Product
{
    Sku = "GB-204",
    Price = 42.00m
};
Object initializers can only set members that are already accessible from the calling code, such as public properties or public fields. A private field cannot be assigned this way from outside the class, regardless of how the object is instantiated.

⚙️ Operator Overloading

If you want to use an arithmetic or comparison operator, such as + or ==, with objects of a class you have written, you must explicitly overload that operator for your class. Both unary operators (which act on a single operand) and binary operators (which act on two operands) can be overloaded this way.

Example: Overloading the + Operator

class Money
{
    public decimal Amount { get; set; }

    public static Money operator +(Money first, Money second)
    {
        return new Money { Amount = first.Amount + second.Amount };
    }
}

With this overload in place, writing combinedTotal = wallet1 + wallet2; becomes legal for two Money objects, calling the overloaded operator method instead of causing a compiler error.

Rules for Overloading Operators

At least one of an overloaded operator's operands must be of the class type you are defining the overload for. You cannot overload an operator to change its meaning purely between two built-in types, such as redefining what + does between two int values; the overload must involve your own custom type.

Operators That Must Be Overloaded in Pairs

Certain related operators must be overloaded together, as a matching pair, rather than one at a time.

Pair Meaning
== and != Equality and inequality
< and > Less than and greater than
<= and >= Less than or equal to and greater than or equal to

Operators That Cannot Be Overloaded

Some operators can never be overloaded in C#, including the plain assignment operator (=) and the conditional logical operators && and ||. These operators always keep their built-in meaning, regardless of what custom types are involved.

📦 Arrays of Objects

An array can hold objects of a custom class exactly as it can hold any built-in type. Because objects are reference types, an array of objects holds the memory addresses, or references, of those objects, not the actual object data itself.

Example: An Array of Objects

Employee[] staff = new Employee[3];
staff[0] = new Employee("Priya", 22.50m);
staff[1] = new Employee("Devon", 19.75m);
staff[2] = new Employee();

Sorting and Searching Object Arrays

To use Array.Sort() or Array.BinarySearch() on an array of custom objects, the class must implement the IComparable interface, which requires writing a CompareTo() method: the method that provides the details of how two objects of that class compare to each other, returning an integer that indicates their relative order.

Example: Implementing IComparable

class Employee : IComparable
{
    public string Name { get; set; }

    public int CompareTo(object other)
    {
        Employee otherEmployee = (Employee)other;
        return this.Name.CompareTo(otherEmployee.Name);
    }
}

With CompareTo() implemented this way, Array.Sort(staff) arranges the Employee objects by name, and Array.BinarySearch() can locate a specific employee within an already-sorted array of them, using exactly the same techniques covered for arrays of built-in types.

🔌 Interfaces and Abstract Methods

An interface consists of abstract methods, methods declared with no body at all, and possibly other members, that any class can use as long as that class agrees to override every abstract method the interface defines with its own working implementation. When a method overrides another, it replaces the inherited or interface-required definition with new, concrete behavior specific to that class.

A name that appears to be a built-in C# class but begins with a capital I, such as IComparable, is almost always an interface rather than a class; this capital-I naming convention is a strong signal throughout the C# standard library.

🗑️ Destructors

A destructor contains the actions you want performed when an instance of a class is destroyed, which most often happens when that instance goes out of scope and becomes eligible for cleanup. A destructor is written using a tilde (~) immediately followed by the class name.

Syntax: A Destructor

class Connection
{
    ~Connection()
    {
        // Cleanup actions performed when this object is destroyed
    }
}
A class can have, at most, one destructor, and a destructor never accepts parameters or an access modifier. Exactly when a destructor executes is controlled by garbage collection rather than by your own code, so you cannot rely on a destructor running at a precise, predictable moment.

🖱️ GUI Application Objects

Every GUI object you work with in Visual Studio, such as a Button or a Form, behaves exactly like the custom objects described throughout this guide: it encapsulates both properties and methods of its own. A Button object, for example, does not just sit on a form passively; it exposes properties like Text and methods that respond to user interaction.

Example: IDE-Generated Property Assignment

this.startButton.Text = "Start";

A line like this one, commonly found in Visual Studio's auto-generated designer code, sets a property, in this case Text, on a Button object named startButton, using exactly the same property syntax covered earlier in this guide.
