Repeating Work Without Repeating Code

Many tasks a program performs need to happen more than once: reading every item in an order, checking every seat in a theater, or printing a schedule for every day of the week. Rather than writing the same statements over and over, C# provides looping structures that repeat a block of code as many times as needed. This guide covers how loops are built and controlled, the three main loop types C# offers, how loops nest inside one another, how totals are accumulated across iterations, variable scope inside a loop, and how to keep loops running efficiently.

🔁 Loop Fundamentals

A loop is a structure that repeats a group of statements. The loop body is the block of statements that executes with each repetition of the loop, and any single execution of a loop's body is called an iteration.

🔂

Loop Body

The block of statements a loop executes with each pass through the loop.

🔢

Iteration

A single execution of a loop's body, from the moment it begins to the moment it finishes.

🎚️

Loop Control Variable

The variable a loop tests to decide whether to keep repeating; it must be initialized, tested, and altered for the loop to function correctly.

Initializing, Testing, and Altering

Every properly written loop handles its loop control variable in three ways: it gives the variable a starting value before the loop begins, it tests the variable's value to decide whether another iteration should run, and it alters the variable's value somewhere within the loop body so that the loop eventually stops.

If a loop control variable is never altered inside the loop body, or is altered in a way that never satisfies the test condition, the loop becomes an infinite loop: a loop that, at least theoretically, never ends on its own.

Incrementing and Decrementing

A loop control variable is most often changed by incrementing it, adding a fixed amount with each iteration, commonly using the ++ operator. Some loops instead count down by decrementing the loop control variable, subtracting a fixed amount with each iteration using --. Which strategy to use depends entirely on whether the task naturally counts up or down.

A loop with an empty body, meaning no statements between its opening and closing braces (or, for a single-statement loop, an accidental semicolon immediately after the test condition), still runs its test condition repeatedly. If the loop control variable is never altered anywhere the compiler considers part of the loop, an empty body is a common accidental cause of an infinite loop.

Escaping an Infinite Loop

If a console program becomes stuck in an infinite loop while running from a command prompt, pressing Ctrl+C (or Ctrl+Break, depending on the environment) forcibly terminates the running program. In a GUI program running from Visual Studio, an infinite loop is instead escaped by clicking the IDE's Stop Debugging button, since a stuck GUI application may never respond to normal window controls like the close button while it is trapped in the loop.

🔄 While Loops

A while loop repeats a block of statements as long as a Boolean expression remains true. That Boolean expression is evaluated every single time the loop considers running its body again, including the very first time.

Syntax: A While Loop

int ticketsRemaining = 5;

while (ticketsRemaining > 0)
{
    Console.WriteLine("Selling one ticket.");
    ticketsRemaining--;
}

Definite vs. Indefinite Loops

Definite (Counted) Loop

The number of iterations is known, or predetermined, before the loop begins. Also called a counted loop.

Indefinite Loop

The number of iterations is not known in advance; instead, the loop is controlled by user input or some other condition that cannot be predicted ahead of time.

A while loop can be written as either kind: it can count a predetermined number of times just as easily as it can run an unpredictable number of times based on what a user enters.

Sentinel Values

An indefinite loop is commonly stopped using a sentinel value: a special value, such as 'N' or -1, that a user enters to signal the loop should stop, rather than a value that represents legitimate data to be processed.

Example: An Indefinite Loop with a Sentinel Value

Console.Write("Enter a donation amount, or -1 to stop: ");
double donationAmount = double.Parse(Console.ReadLine());

while (donationAmount != -1)
{
    Console.WriteLine("Thank you for your donation!");
    Console.Write("Enter another donation amount, or -1 to stop: ");
    donationAmount = double.Parse(Console.ReadLine());
}

Here, -1 is the sentinel value; it is not a real donation amount, only a signal that tells the loop to stop asking for more input.

🔢 For Loops

A for loop is built specifically for situations where the number of iterations is predetermined. It brings together everything a counted loop needs, the starting value of the loop control variable, the test condition that controls whether the loop continues, and the expression that alters the loop control variable, all in one convenient statement.

Syntax: A For Loop

for (int day = 1; day <= 7; ++day)
{
    Console.WriteLine("Forecast for day {0}", day);
}

The keyword for begins C#'s shorthand method for writing a counted loop. Reading the parentheses from left to right: int day = 1 initializes the loop control variable, day <= 7 is the test condition checked before every iteration, and ++day is the expression that alters the loop control variable at the end of every iteration.

A valid for statement needs all three components separated by semicolons. Leaving one out, such as omitting the initialization and writing only for(counter < 21; ++counter), is a syntax error; the missing initialization component must still be present, even if it is left blank, as in for(; counter < 21; ++counter).

Blocks in a For Loop

Just as with an if statement, the statements belonging to a for loop's body can be grouped inside curly braces to form a block, allowing any number of statements, not just one, to repeat with each iteration.

The Step Value

The amount by which a loop control variable changes on each cycle of a for loop is called the step value. In the example above, the step value is 1, since ++day adds exactly 1 each time, but a for loop can just as easily use a different step value, such as day += 2 to count by twos.

Block Scope

A loop control variable declared directly inside a for statement's parentheses, as day is above, exists only within that for loop's block. This is called block scope: the variable is in scope (usable) only from the point it is declared until the closing brace of that block, and it goes out of scope the moment execution leaves the loop.

Referring to a for loop's control variable after the loop's closing brace produces a compiler error, because that variable no longer exists once execution leaves the block it was declared in. If a value needs to be used after the loop finishes, it must be declared in a scope that includes both the loop and the code that follows it, such as immediately before the loop begins.

🔃 Do Loops

A do loop, also called a do...while loop, checks its Boolean expression at the bottom of the loop, after the loop body has already executed once. This guarantees that a do loop's body always runs at least one time, no matter what the test condition evaluates to.

Syntax: A Do Loop

int attemptsUsed = 0;

do
{
    attemptsUsed++;
    Console.WriteLine("Attempt number {0}", attemptsUsed);
} while (attemptsUsed < 3);
To write a properly functioning do loop, initialize the loop control variable before the loop begins, just as with any other loop, and make sure the loop body alters that variable somewhere before reaching the while test at the bottom. Because the test happens after the body runs, it is especially easy to forget the altering step when writing a do loop, which can just as easily create an infinite loop as any other kind.

⬆️⬇️ Pretest vs. Posttest Loops

Pretest Loop

Checks its Boolean expression at the "top" of the loop, before the body has a chance to execute even once. Both the while loop and the for loop are pretest loops.

Posttest Loop

Checks its Boolean expression at the "bottom" of the loop, after each repetition has already occurred. The do...while loop is C#'s posttest loop.

Why the Difference Matters

Because a pretest loop's condition is checked before the body ever runs, a pretest loop's body can execute zero times if the condition starts out false. A posttest loop's body, by contrast, always executes at least once, since the condition is not checked until after that first execution has already happened.

🪆 Nested Loops

A nested loop is a loop placed entirely inside the body of another loop. The loop on the outside is called the outer loop, and the loop contained within it is called the inner loop. For every single iteration of the outer loop, the inner loop runs through its own complete set of iterations from start to finish.

Example: A Nested Loop

for (int floor = 1; floor <= 2; ++floor)
{
    Console.WriteLine("Floor {0}:", floor);

    for (int room = 1; room <= 3; ++room)
    {
        Console.WriteLine("  Room {0}", room);
    }
}
// Output:
// Floor 1:
//   Room 1
//   Room 2
//   Room 3
// Floor 2:
//   Room 1
//   Room 2
//   Room 3

Here, floor controls the outer loop and room controls the inner loop. The inner loop completes all three of its iterations for floor 1 before the outer loop advances to floor 2, at which point the inner loop runs through all three rooms again from the beginning.

Nested loops must be constructed so the inner loop is entirely contained within the outer loop's body; the two loops can never partially overlap. An inner loop's opening and closing braces must both appear somewhere between the outer loop's opening and closing braces.

➕ Accumulating Totals

An accumulator variable collects a running total across the iterations of a loop. Totals that are summed one value at a time within a loop, rather than all at once, are described as accumulated totals.

Example: Accumulating a Total

double dailySalesTotal = 0;
double[] saleAmounts = { 45.00, 12.50, 89.99 };

foreach (double sale in saleAmounts)
{
    dailySalesTotal += sale;
}

Console.WriteLine("Total sales: {0:C2}", dailySalesTotal);
An accumulator variable must be given a defined starting value, almost always zero, before it is used to accumulate anything. C# will not compile code that reads from a local variable before it has been assigned a value, precisely to prevent the variable from holding a garbage value: an unpredictable, leftover value with no defined meaning that a variable would otherwise contain before it is explicitly initialized.

Business programs frequently rely on accumulated totals, such as adding up every transaction in a day's sales, every hour an employee worked in a pay period, or every item in a customer's order, to arrive at a single final figure.

🔍 Scope

Scope is the area of a program in which a variable or named constant is known and can legally be used. A variable declared inside a loop's block, whether that block belongs to a for, while, or do loop, is in scope only for statements within that same block.

Example: A Variable Going Out of Scope

for (int i = 0; i < 5; ++i)
{
    int squareValue = i * i;
    Console.WriteLine(squareValue);
}

// Console.WriteLine(squareValue); // Error: squareValue is out of scope here

If a program defines a variable inside a loop and then tries to use that same variable in code that follows the loop, the program will not compile. The issue is that the variable went out of scope the moment the loop's closing brace was reached; the fix is to declare the variable before the loop begins, in a scope broad enough to include the code that needs it afterward.

⚙️ Loop Optimization

Because a loop's body may execute many times, even small inefficiencies inside it can add up. A few habits help keep loops running efficiently.

Move Unchanging Calculations Outside the Loop

If an arithmetic operation inside a loop body always uses values that never change while the loop runs, performing that calculation once before the loop begins, rather than recalculating it on every iteration, avoids needless repeated work.

Example: Moving an Invariant Calculation Out of a Loop

// Less efficient: taxRate and basePrice never change,
// yet salesTax is recalculated every single iteration
for (int i = 0; i < orderCount; ++i)
{
    double salesTax = basePrice * taxRate;
    // ...use salesTax...
}

// More efficient: calculate once, before the loop begins
double salesTax = basePrice * taxRate;
for (int i = 0; i < orderCount; ++i)
{
    // ...use salesTax...
}

Ordering Short-Circuit Evaluation Strategically

Compound Boolean expressions used to control a loop still use short-circuit evaluation: each part of the expression is evaluated only as much as necessary to determine whether the whole expression is true or false. Placing the condition that is cheapest to check, or most likely to determine the result on its own, first in the expression can reduce how often the second, more costly condition needs to be evaluated at all.

The order of expressions in a compound Boolean expression matters least to loop performance when every part of the expression is equally simple and inexpensive to evaluate; in that situation, no ordering offers a meaningful advantage over any other, since there is little processing cost to save regardless of which part is checked first.

Loop Fusion

Loop fusion is the technique of combining two separate loops into a single loop, when doing so does not change the program's results. Loop fusion is most appropriate when two loops iterate the exact same number of times and neither loop depends on results the other loop produces during its own iterations; combining them then avoids the overhead of managing and testing a second loop control variable separately.

Matching iteration counts alone does not automatically make two loops safe to fuse. If one loop's iterations depend on data the other loop is still in the process of producing, or if the two loops need to run in a specific order relative to each other for the program to work correctly, fusing them can change the program's behavior and should be avoided.

🖱️ Loops in GUI Applications

Loops work identically inside a GUI application's code as they do in a console program, but event-driven GUI programs sometimes need fewer explicitly coded loops than their console counterparts.

Why GUIs Often Need Fewer Coded Loops

In a console program, a coded loop is frequently needed just to keep asking the user for more input until a sentinel value arrives. In a GUI program, the user naturally provides that repetition themselves, clicking a button as many times as they want a task to repeat. Each click triggers its own separate execution of an event-handling method, so the repetition comes from user interaction with the interface rather than from a loop written directly in the code.

This does not mean GUI programs never use loops. Processing every item already stored in a collection, such as every line of a customer's order or every row loaded from a file, still calls for a coded loop inside a GUI application, exactly as it would in a console program.
