Organizing Code into Reusable Units

As a program grows, repeating the same statements again and again makes it harder to read, harder to fix, and harder to trust. Methods solve this by packaging a task into a single named unit that can be called wherever it is needed. This guide covers what a method is and how it is structured, how accessibility and static modifiers control who can use a method and how, variable scope inside a method, how parameters and arguments work, how methods return values, how arrays behave when passed to a method, the several valid ways to write Main(), and how methods are used inside GUI applications.

🧩 Method Fundamentals

A method is an encapsulated series of statements that carries out a task. Organizing a program's logic into methods, rather than repeating the same statements throughout a program, helps avoid code bloat: a program that is unnecessarily large and repetitive because the same logic appears in multiple places instead of being written once and reused.

Calling Methods and Called Methods

When your code uses a method's name to make that method perform its task, you are calling the method. The method that does the calling is known as the calling method, and the method being used is the called method. A method that uses another method is therefore considered a calling method with respect to whatever it calls.

Implementation Hiding

Implementation hiding is the technique that allows a programmer to change how a method works internally without affecting any program that already uses that method, as long as the method's name, parameters, and return type stay the same. A method client is any program or code that uses a method without needing to know how that method accomplishes its task internally, much like a black box: any device you can use without understanding its inner workings.

Implementation hiding is what lets you improve or rewrite a method's internal logic later, perhaps to make it faster or fix a bug, without forcing every program that already calls that method to change anything about how it calls it.

🏗️ Method Structure

A method declaration, also called a method header, follows a specific order of parts, some required and some optional.

Syntax: A Method Declaration

// [accessibility] [static] returnType MethodName(parameterList)

public static double ConvertMilesToKilometers(double miles)
{
    return miles * 1.60934;
}
Part Required? Purpose
Accessibility (public, private) Optional Controls which other code can call the method
static Optional Marks the method as callable through the class itself, without an object
Return type (or void) Required The data type of the value the method sends back, or void if it sends nothing back
Identifier Required The method's name
Parameter list Required (parentheses), even if empty Declares what data, if any, the method accepts when called

Every C# method begins with this same pattern: an optional accessibility modifier, an optional static modifier, a required return type, a required identifier, and a required parameter list enclosed in parentheses, even when that parameter list is empty. The statements that make up the method's body follow inside curly braces.

A method with an empty parameter list, written as simply (), is a completely valid method; it just accepts no arguments when it is called. Every method requires the parentheses themselves, whether or not anything appears inside them.

The Return Type

A method's type is determined by its declared return type. If a method's header shows int as its return type, that tells you the method sends an integer value back to whatever called it. The keyword void in a method header, in place of a return type, means the method performs its task but does not send any value back to its caller at all.

Indentation Convention

By convention, C# programmers indent the statements inside a method's body, not the method header itself. The header starts flush with the surrounding code, while every statement within its curly braces is indented one level in, making the boundaries of the method body easy to see at a glance.

🔐 Accessibility and Modifiers

Private vs. Public Access

If a method declaration does not include an accessibility modifier at all, C# treats that method as private access by default: usable only from within the class that contains it. Adding the public keyword instead grants public access, allowing the method to be called from other classes as well.

Leaving off an accessibility modifier does not make a method public by default; C# always defaults to private access unless public is explicitly written in the method header.

Fully Qualified Names

Calling a method that belongs to a different class often requires its fully qualified name: the class name followed by a period and the method name, such as Bakery.MixDough(). Using a method's complete name this way makes clear exactly which class the method belongs to.

Static vs. Nonstatic Methods

A static method is called by referring to the class itself, without needing an object created from that class. A nonstatic method, which is the default unless static is explicitly written, instead requires an object reference; a nonstatic method call always needs an actual object to call it on, rather than the class name alone.

Example: Static vs. Nonstatic Method Calls

// Static method: called through the class name
double kilometers = UnitConverter.ConvertMilesToKilometers(10);

// Nonstatic method: requires an object reference
Robot helper = new Robot();
helper.Greet();

🔍 Scope

A local variable or local constant is one declared within a method's body. Locally declared items are visible, meaning usable, only within the specific method where they are declared; they are entirely unknown to every other method in the program.

A variable declared inside one method cannot be referenced by name inside a different method, even another method in the same class. Once execution leaves the method where a local variable was declared, that variable is no longer available anywhere; this is exactly why it is described as being only in scope until the end of its own method.

📥 Parameters and Arguments

Formal Parameters vs. Actual Parameters

A formal parameter is a variable listed in a method's header that is designed to accept a value when the method is called; it is the placeholder that appears in the method declaration itself. An actual parameter, more commonly called an argument, is the real value supplied in the method call that gets copied into the formal parameter.

Example: Formal Parameters vs. Arguments

// mealCost is the formal parameter, declared in the header
private static void SuggestGratuity(double mealCost)
{
    double gratuity = mealCost * 0.18;
    Console.WriteLine("Suggested gratuity: {0:C2}", gratuity);
}

// 42.50 is the actual parameter (argument) in this call
SuggestGratuity(42.50);

A formal parameter that receives a copy of the value passed to it is described as an example of a parameter passed by value: the method works with its own separate copy, so changes made to that parameter inside the method have no effect on the original argument back in the calling method.

Matching Arguments to Parameters

The arguments passed in a method call must match the method's declared parameters in both number and type, with two notable exceptions.

Default Arguments

A parameter can be given a default value in the method declaration itself, which allows the method to be called with fewer arguments than parameters, as long as the omitted parameters are the ones with defaults.

Type Promotion

An argument does not always need to exactly match its parameter's declared type. A value can be automatically promoted to a larger, compatible type, such as passing an int argument to a double parameter.

C# still requires a data type to be written for every single formal parameter in a method's header, even when two consecutive parameters happen to share the same type. There is no shorthand that lets you list a type once and apply it to multiple parameter names.

Nested Method Calls

Using the result of one method call directly as the argument to another method call is called a nested method call. C# evaluates the inner method call first, then passes its returned value into the outer method call.

Example: A Nested Method Call

Console.WriteLine(ConvertMilesToKilometers(10));
// ConvertMilesToKilometers(10) is evaluated first, and its
// returned value becomes the argument passed to WriteLine()

↩️ Return Values

The return statement sends a value from an executing method back to whatever method called it. A C# method can return, at most, one value to its caller; there is no way for a single method call to hand back two separate return values at once.

Example: A Method with a Return Value

private static bool IsEligibleForDiscount(int customerAge)
{
    return customerAge >= 65;
}

Boolean-Returning Methods in Conditions

A method that returns a bool value can be called directly inside a conditional expression, exactly as if it were a Boolean variable.

Example: Calling a Boolean Method in an if Statement

if (IsEligibleForDiscount(age))
{
    Console.WriteLine("Senior discount applied.");
}

A Boolean-returning method can also control a loop directly, such as in the test expression of a while loop, since the loop simply needs an expression that evaluates to true or false on each pass.

When a compound Boolean expression combines two method calls with && or ||, short-circuit evaluation can prevent the second method from ever being called. If that second method is expected to run every time, such as one that also updates some other value as a side effect, relying on it to always execute inside a short-circuited expression can produce unintended results.

📦 Passing Arrays to Methods

Passing a Single Array Element

Passing a single element of an array with a built-in type, such as one int or one char from an array, behaves exactly like passing any other value: it is passed by value. The method receives its own separate copy of that element, so changing the parameter inside the method does not affect the original array element back where the array was declared.

Example: Passing a Single Array Element

char[] passwordChars = { 's', 'i', 'l', 'k' };

private static void ReplaceCharacter(char letter)
{
    letter = 'u';
}

ReplaceCharacter(passwordChars[1]);
// passwordChars still contains { 's', 'i', 'l', 'k' };
// only the method's local copy of the character changed

Passing an Entire Array

Passing an entire array, rather than one of its elements, works differently. Because arrays are objects, passing a whole array to a method is passed by reference: the method receives the array's memory address, giving it direct access to the actual values stored in the original array back in the calling code, not a separate copy.

Example: Passing an Entire Array by Reference

private static void DoubleAllValues(int[] numbers)
{
    for (int i = 0; i < numbers.Length; ++i)
    {
        numbers[i] *= 2;
    }
}

int[] scores = { 10, 20, 30 };
DoubleAllValues(scores);
// scores is now { 20, 40, 60 }, because the method
// modified the original array's actual elements

The square brackets, [], placed after the data type in a parameter list, as in int[] numbers, are exactly what indicate to the compiler that a parameter is an entire array rather than a single value of that type.

Passing multidimensional or jagged arrays to a method works the same way, by matching the appropriate bracket pattern in the parameter list. A rectangular array parameter uses double[,], while a jagged array parameter uses int[][], mirroring however the array itself was declared.

🚪 Main() Method Variations

C# allows several valid ways to write the Main() method header, and it is useful to recognize each of them, since different projects and different needs call for different versions.

Main() Variation When to Use It
static void Main() The conventional, most common form; no command-line arguments needed, nothing returned to the operating system
static void Main(string[] args) Accepts command-line arguments typed after the program's name when it is run
static int Main() Returns an integer exit code to the operating system or calling program when the application finishes
public static void Main() Allows Main() to be called from another class using its fully qualified name, though there is rarely a practical reason to do this

If no access specifier is written for Main(), it defaults to private access, the same default that applies to any other method. In practice, Main() is conventionally left with private access; C# programmers rarely add public to it. Main() always includes the static keyword because it is associated with its containing class as a whole, not with any individual object created from that class.

Example: Reading Command-Line Arguments

static void Main(string[] args)
{
    if (args.Length > 0)
    {
        Console.WriteLine("First argument: {0}", args[0]);
    }
}

A program compiled with this Main() header, named HandyTool, would be launched from a command prompt simply by typing its name followed by whatever arguments it should receive, such as HandyTool report.txt, with the arguments separated from the program name and from each other by spaces.

Ending a static int Main() method with return 0; is a common convention that signals successful completion to the operating system or to whatever program launched it; by convention, a return value of 0 indicates success, while a nonzero value typically signals that some kind of error occurred.

🖱️ Methods in GUI Applications

When you place a control such as a Button on a form in the Visual Studio IDE and double-click it, Visual Studio automatically generates an empty event-handling method header for you, ready to be filled in.

Example: An Automatically Generated Click Method

private void okButton_Click(object sender, EventArgs e)
{

}

The two parameters shown here, sender and e, are generated automatically by the IDE as part of the standard pattern every event-handling method follows; you do not need to write this parameter list yourself.

Because a generated Click method is associated with a Form object rather than with the class as a whole, it is, by default, a nonstatic method. Methods associated with Form objects are typically nonstatic for exactly this reason.

Scope Across Multiple Event Methods

A GUI application frequently defines several separate event-handling methods, one for each control's event, such as a Click method for one button and another Click method for a different button. When a variable or constant needs to be available to more than one of these event-handling methods, it must be defined outside of any single method, within the Form class itself, rather than inside just one event handler.

If a variable is instead declared inside just one event method, ordinary method scope rules still apply: that variable is only visible within that one method and unknown to every other event-handling method in the class, even though they all belong to the same form. Because variables are frequently needed by multiple event-handling methods in a GUI application, you must constantly stay aware of each variable's or constant's scope when deciding where to declare it.
